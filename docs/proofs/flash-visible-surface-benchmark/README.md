# Visible-surface benchmark: first implementation

This is a **development pilot**, not a decision to replace FLASH's tracker. The benchmark compares point identity before any SAM/depth/rigid-fit correction. Six 31-frame YCBInEOAT clips use pose-derived material-point references; the local 91-frame dowel rotation has no independent point labels and is visual/diagnostic evidence only. All adapters use the same source RGB-D frames, query pixels and camera intrinsics for a clip.

[Labelled mustard comparison](mustard_labeled_comparison.mp4) shows model points in cyan and independent pose-derived reference points in magenta. [Dowel rotation comparison](dowel_comparison.mp4) shows the complete 91-frame interval, including lost and drifting points. The thin white outline is the segmentation mask; staying inside it does **not** prove point identity.

The [labelled results](PILOT.md) include missing visible points in coverage denominators. The [paced replay](PACED.md) releases frames at recorded timestamps and probes a separate 30 Hz consumer. TrackEverything runs here as a full-clip windowed model, possibly using future frames, so its offline FPS is not a causal publication rate. The other point frontends run frame by frame. All GPU measurements used the rig's RTX 5090 and preloaded checkpoints, but not SAM, FLASH fitting, robot IO or recording. Model load and first-frame warmup are recorded separately.

The first visual comparison exposed an adapter error: BootsTAPIR scaled queries using its default 640-pixel width before its `initialize` call learned the 848-pixel dowel camera width. Its initial median offset was 72.9 pixels. Passing the actual image dimensions before query creation reduced that offset to 1.2 pixels. All reported BootsTAPIR runs were regenerated after this correction. This is why an input/output contract check and a source-frame image review are required before comparing model quality.

Reference limitations remain material. YCBInEOAT's annotated object pose transports a point seeded from the _measured_ first-frame depth; the reference point often differs from later measured depth by several millimetres. Its mask/depth visibility gate excludes unsupported points, but it does not make those labels submillimetre truth. The clips were chosen during adapter development, all from one public source, and have no held-out split. The one-third-second startup in the paced neural runs mostly reflects first-frame model warmup; after that they keep up with the 30 Hz local source in this short probe. These observations do not establish full-loop performance or reliability through occlusion.

Run the tools from the repo root. `prepare-local` freezes source indices, queries, intrinsics and first-frame hashes; `flash_surface_ycbineoat` adds pose-derived labels. Adapters save the same `prediction.npz` fields (`frames`, `queries`, `xy`, `xyz`, `visible`, source type), per-stage timing and optional paced publication traces. `flash_surface_benchmark evaluate` checks the recorded mask/depth as a **diagnostic**, and scores accuracy only when independent labels exist. `flash_surface_report` produces equal-clip summaries; `flash_surface_render` renders the full interval with source-time pacing. Model-specific Python environments and checkpoints remain outside git. Do not mix depth lifted from the predicted pixel with native model 3D depth as though their depth residuals were comparable.

The full [protocol](../../../src/lerobot/policies/flash/docs/visible_surface_benchmark.md) still calls for an additional public RGB-D source, a frozen holdout, longer moving intervals, query growth, common rigid fitting, more candidate models and integrated segmentation/robot-loop load. The current scores cannot choose a production tracker.
