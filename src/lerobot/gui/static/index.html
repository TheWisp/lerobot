    This host needs root

    The host still needs Docker or the NVIDIA toolkit installed, and its SSH user cannot become root without a password. It is used for this attempt only — not saved to the host profile, and not written to the run record.

    Add training host

    Use a ~/.ssh/config alias (e.g. lab-gpu1) or user@host. Auth uses your local SSH setup — the GUI server never reads your private keys.

    A Nebius VM is spawned when a run starts and destroyed when it ends, using the Nebius connection configured on this server. You pay the vendor directly — know the rates ↗.

    Nebius connection

    One service-account key, stored on this GUI server and used to spawn and tear down the cloud GPUs. Note: it's saved on the server and usable by anyone who can reach the GUI (there's no per-user login), and it bills your Nebius account — so set it up only on a trusted network.

    How do I get a key?
    A Nebius tenant admin creates a service account and an authorized key — via the Nebius console ↗ (IAM → Service accounts → Upload authorized key), or the CLI: 
    nebius iam service-account create --name lerobot-training
nebius iam auth-public-key generate \
  --service-account-id <SA_ID> --output sa-key.json
    Paste the contents of sa-key.json below. Docs: authorized keys ↗ · CLI ↗. The Project & Subnet IDs are in the console (they start with project- / vpcsubnet-).

    Report a bug

    Stored on the GUI server under ~/.cache/lerobot/bug_reports/. Not sent anywhere else.
