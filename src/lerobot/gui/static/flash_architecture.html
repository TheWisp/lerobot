How FLASH tracks one object

The live camera and recorded videos use the same tracking code. For each object, it combines what the camera sees now with motion clues and the surface remembered from earlier frames.

Time key: t is the frame being processed; t−1 is the previous processed frame; <t means any earlier frame. O[t] is measured surface now; S[<t] is the confirmed surface stored before now; H[t] is an inferred motion hint; P[t] is the estimated pose published for now.

2. How the surface grows over time

Growth is separate from accepting a pose. Only confirmed patches enter S, so a new patch cannot validate the same frame that produced it.

Before frame t S[<t] · active

Starts from the first usable depth measurement. Later fits read the union of all confirmed patches.

At frame t O[t] · measured

Replacement rule today: a newer view does not automatically replace the first patch. The map combines confirmed measurements. Its size limit may evict a patch that covers little unique surface; that is a memory rule, not a judgment that a newer patch is more accurate. Incorrect old geometry is not automatically repaired. Separately, the first image remains a texture anchor; the fresh-session default uses the latest accepted image for partial-view geometry checks.

3. Which pose is shown?

This is the loop after initialization. “Enough O[t]” asks only whether the current mask is nonempty and its cleaned depth has at least three 3D points spanning a plane. It permits a fit attempt; it does not certify a pose. Select a situation to trace its path.

Why Kalman? A small visible patch may constrain depth well but leave tilt uncertain. Kalman keeps a pose and its uncertainty across frames: predict first, then let the new fit correct the directions it actually measures well. It can reject a jump that is too large for their combined uncertainty. Geometry checks still apply.
Scope: fitting can run without Kalman; it adds memory and uncertainty handling. The flow below shows fresh-session defaults with Kalman enabled. Older saved results may use other settings.

The fit passes the depth and mask checks. After an optional Kalman update, it is checked again and published as observed.

    Observed → update memory

    Save this frame's RGB, depth, mask and accepted pose as the reference for later image matching. Add depth points only after the stricter growth checks. Object association can add new point IDs from an accepted observation; only a new reference replaces its existing coordinates. Scene groups update before fitting and receive no fitted pose.

    Predicted or lost → no surface growth

    Prediction can move the displayed surface but cannot measure hidden shape. “Lost” means no pose is published for this frame; the object may still be visible.

    4. What each step measures

    These are current diagnostic names and the decisions they inform, not calibrated probabilities of a correct pose. The live camera uses fresh-session settings; a saved video keeps the settings recorded when it was processed. Both views expose these settings through their pipeline controls.

    The live scene snapshot keeps the fit and prediction checks with its RGB-D frame, including rejected poses for diagnosis only. Depth conflicts identify whether they occurred in the current image or a retained image. These diagnostic poses are never displayed as accepted tracking. The same frame result is retained in saved video output or live rolling history.

    O[t] · can we attempt a fit?

    Read: clean_count, current mask, 3D point spread.

    Gate: nonempty mask, at least three cleaned depth points with two independent spatial directions. This is a minimum input check, not pose confidence.

    Tune: mask_margin_px, depth_span_m, depth_outlier_sigma.

    H[t] · how well did points move?

    Read: matches, inliers, match_residual_mm; group support count and disagreement.

    Gate: enough mutually consistent tracked points. A surrounding group joins only after sustained co-movement.

    Tune: ransac_distance_m, min_inliers, fit_threshold_m, support_confirmation_s.

    Scene groups · membership and motion

    Read: group count, confirmed/supported groups, measured inlier count, motion residual, predicted hidden point count and group update time.

    Gate: visible measurements must fit one rigid motion within tolerance. A point leaves after its measured disagreement persists for the split duration; points or groups join only after the longer co-motion duration. Missing points retain predicted positions, but do not measure motion.

    Tune: fit_threshold_m, min_inliers, split_tolerance_m, split_confirmation_s, merge_tolerance_m, merge_confirmation_s, support_confirmation_s, max_hidden_s, max_points, max_groups, motion_hypotheses.

    Surface fit · quality within the budget

    Read: geometry_cost, evaluations, and validation_count.

    Optimize: surface alignment, with outline coverage and image/group evidence helping choose the fit. A lower cost cannot excuse a failed geometry check.

    Tune: the selected matcher's numerical iteration budget and the fitting weights. One local solve; no outer restart search.

    S[<t] ↔ O[t] · does the pose fit?

    Read: surface_median_mm, observed_overlap, visible outlier fractions, and scene_depth_coherent_protrusion.

    Gate: no coherent protrusion into measured empty space; enough overlap and no more than the configured outlier fraction. Missing depth is unknown, not a conflict.

    Tune: depth_tolerance_m, min_overlap, max_visible_outlier_fraction. Outline coverage is a soft preference, not a hard requirement.

    Kalman · prediction and correction

    Read: kalman.innovation_squared versus kalman.innovation_limit, and the pose covariance.

    Predict: move the previous pose with measured group motion when available; account for supplied camera motion. Add uncertainty for motion error and elapsed time.

    Correct: compare fitted and predicted poses using their combined uncertainty. Reject excessive disagreement. Otherwise combine them, giving more weight to the more certain estimate in each direction, then recheck geometry.

    Limits: uncertainty is a joint 6D covariance, not one confidence percentage. Observation uncertainty currently comes from depth-surface constraints; it does not yet include the outline and texture constraints. Fresh-session defaults keep the disagreement check even if the prediction fails geometry.

    Tune: process noise, measurement noise, and compatibility_probability; these are assumptions, not measured correctness.

    Growth · may S gain new points?

    Which surface: map_version_used and surface_frames_used identify the confirmed map read by this frame. accepted_frame_before identifies the saved RGB-D reference; image_source_frame identifies the actual source used for image matching.

    Read: growth.observed_overlap, growth.patch_consistent, growth.admitted_points, map_points.

    Gate: stricter overlap with active S, sufficient consistency with retained views, then confirmation by a later measured frame. Only then does a pending patch become active.

    Tune: growth_agreement_m, growth_min_overlap, patch_consistency, patch_overlap, confirmations.

    Published result · what supports it?

    Read: output status, prediction_source, prediction_age_s, covariance and the rejection reason.

    Meaning: observed passed this frame's checks; predicted relies on earlier evidence and motion. Lost means no pose is published. These labels do not guarantee real-world correctness.

    5. Inspect the same result from either source

    Each call to the shared frame loop returns poses, rejection reasons, geometry checks, covariance, group points and the frame/map IDs it used.

    Video examples → saved frame results

    The player reads these results alongside the recorded RGB-D, masks, image matches and surface versions. Inspecting a frame does not rerun the tracker.

    Live camera → rolling frame history

    Every captured RGB-D frame enters history from camera start, including frames before selection and frames skipped by the tracker. A processed result adds masks, matches and surfaces to its frame later. Scrub recent frames or save the window across sessions.

    Compression and disk writing run on a separate thread. The default window is 60 seconds. If the writer cannot keep up, the UI reports dropped camera frames. A full disk stops recording with an error. Saved windows preserve evidence for inspection, not a complete tracker checkpoint.

    Live and video settings use the same typed controls and units. Live changes apply when opening the camera; video changes apply on rerun. Segmentation controls are hidden for video reruns that reuse recorded masks.
