# Saved masks — a test pass

For someone who has not read the design. It is
[saved_masks.md](saved_masks.md); you should not need it to do this.

**Where:** <http://fc500t:9137> — already open on `screenshots/mask_segments_demo`,
a throwaway dataset built for this. Break it freely; it is regenerated by a
script and nothing else uses it.

Every step below carries a **Pass if** line. Check that, not just that the click
worked — several of these steps look fine while doing nothing at all, which is
how an earlier round of this checklist passed against a feature that was writing
no masks whatsoever.

## The one idea

Segmentation is expensive to compute and free to delete. So **nothing here ever
overwrites a mask.** Every write fills gaps and leaves what is already there
alone. If you dislike what is stored you delete it, then fill again.

That is why a mask has **three** states, not two:

| on the track   | means                          | training      | a later pass    |
| -------------- | ------------------------------ | ------------- | --------------- |
| **filled** bar | detected                       | uses it       | leaves it alone |
| **hollow** bar | disabled — stored but withheld | ignores it    | leaves it alone |
| faint rail     | absent                         | nothing there | fills it        |

"Disabled" exists because otherwise _"this detection is wrong here"_ and
_"nothing was found here"_ are the same thing in storage — and the next pass
would put the wrong detection straight back.

## What is in the dataset before you start

Two episodes of 90 frames, two cameras (`front`, `left_wrist`), from real rig
footage: a green ring and some coloured blocks on a dark tray. The masks are
real SAM3 detections, with gaps cut into them on purpose:

| label          | frames 0–29 | 30–44        | 45–59    | 60–74      | 75–89    |
| -------------- | ----------- | ------------ | -------- | ---------- | -------- |
| `green ring`   | detected    | **disabled** | detected | **absent** | detected |
| `yellow block` | detected    | detected     | absent   | absent     | absent   |

`tray` is deliberately **not** in the vocabulary. You add it in step 15, which
is what gives that step something real to write.

Segmentation costs about **80 ms per frame per camera** on this machine
(measured), so playing an episode with Apply on takes roughly 15 seconds — slow
on purpose. That is the point of lock-step: what you watch is what lands.

## Checklist

Open episode 0 and find the `masks.front` row on the timeline. It has one lane
per label.

### Reading the track

- [ ] **1.** Look at the `green ring` lane.
      **Pass if:** you can see three distinct stretches — filled, hollow, and a
      faint rail — and can tell filled from hollow at a glance without leaning
      in. Their boundaries should land where the table above says.
- [ ] **2.** Look at the `front` camera tile.
      **Pass if:** the ring is visibly tinted and the block visibly blurred —
      the effects from the Inspector applied to the stored masks. This is the
      composite a model would be fed, not a preview.

### Editing a range

- [ ] **3.** Drag across frames ~5–25 of the `green ring` lane, then click once
      somewhere else.
      **Pass if:** the drag selects a range, and the single click only moves the
      playhead — it must **not** select anything editable, and must **not**
      toggle the stretch you clicked on.
- [ ] **4.** Re-select ~5–25 and click the **filled** stretch inside it.
      **Pass if:** those frames go hollow immediately, and the pending-edit
      count on the bottom bar reads 1.
- [ ] **5.** Click the same stretch again.
      **Pass if:** it returns to filled **and** the pending count returns to
      **0** — not 2. The queue records where you want to end up, not how many
      times you clicked.
- [ ] **6.** Stage one edit, then tick **show pending edits**.
      **Pass if:** the amber band covers only the `green ring` lane over the
      frames you selected — not the whole `masks.front` row, and not the whole
      episode.
- [ ] **7.** Hover near the **right-hand edge** of a stretch.
      **Pass if:** exactly one red `×` appears, at that edge, and it stops
      appearing when the cursor is more than a thumb's width away. Press it.
      **Pass if:** those frames become a faint rail.
- [ ] **8.** Press **Discard** on the bottom bar and confirm.
      **Pass if:** the lane returns to exactly the state in the table above and
      the pending count is 0. Nothing reached disk.
- [ ] **9.** Redo one edit and press **Save**.
      **Pass if:** the `front` camera tile visibly changes within a second or
      two, and the pending count returns to 0. If the tile does not change, say
      so — that is the failure this step exists to catch.

### Treatments (Inspector, top section)

- [ ] **10.** Find the **Dataset** section.
      **Pass if:** it lists `green ring` and `yellow block` by name with one
      effect each, and says _applies to every camera_. There must be no
      per-camera copy of the list — one object is one label, however many
      cameras see it.
- [ ] **11.** Change `green ring` from `tint` to `blur`.
      **Pass if:** a Save/Cancel appears **next to that row**, and the
      timeline's bottom bar pending count stays at **0** — config and frame data
      commit through different controls on purpose.
- [ ] **12.** Press that row's Save.
      **Pass if:** the ring in **both** camera tiles switches from tinted to
      blurred. One camera changing and not the other is a failure.

### Segmenting

- [ ] **13.** In **Overlays**, pick `sam3_track`.
      **Pass if:** the object rows arrive pre-filled with `green ring` and
      `yellow block` — the vocabulary the dataset already carries — rather than
      empty.
- [ ] **14.** Look over the Overlays panel.
      **Pass if:** there are **no** effect or tint controls anywhere in it.
      Effects are dataset-wide and live only in the Inspector.
- [ ] **15.** Add a third object, `tray`, and tick **Apply — write masks while
      playing**. Then wait, without pressing play.
      **Pass if:** nothing happens. Ticking is not a write — it arms the mode.
      The pending-edit count stays 0 and no lane changes. If masks start
      appearing on their own, that is the failure.
- [ ] **16.** Now press **play**.
      **Pass if:** playback is visibly slower than normal (~0.3×) and the lanes
      fill _behind the playhead as it goes_ — the `green ring` rail over frames
      60–74 and a new `tray` lane. The pending count rises. Playback is
      lock-step: the playhead only moves once the frame it is on has been
      segmented, so it should never run ahead of the filling.
- [ ] **17.** **Pause** part-way through.
      **Pass if:** it stops where you paused; the frames behind the playhead are
      staged and the frames ahead are untouched. Nothing has reached the dataset
      yet — this is all still pending.
- [ ] **18.** Press **Discard** on the bottom bar and confirm.
      **Pass if:** the whole run disappears — every lane returns to the table
      above and the pending count is 0. A run is one edit, so Discard throws all
      of it away, not the last frame.
- [ ] **19.** Play with Apply on again, pause, and this time press **Save**.
      **Pass if:** the pending count returns to 0 and the lanes keep what the run
      filled. Now it is on disk.
- [ ] **20.** Play over the same stretch once more.
      **Pass if:** nothing changes. A pass adds; it does not replace.
- [ ] **21.** Look at `green ring` over frames 30–44, disabled since before you
      started and now played over twice.
      **Pass if:** they are **still hollow**. This is the one that matters most
      — if a run can un-disable a mask, a bad detection you rejected is back in
      training. Say so loudly.

### Whole dataset

- [ ] **22.** Inspector → **Fill gaps across all episodes…**.
      **Pass if:** each label shows how many episodes carry it. That number is
      the point: a label in 1 of 274 episodes is local to it, and running it
      everywhere costs hours and returns false positives.
- [ ] **23.** Untick every label and press Run.
      **Pass if:** it refuses, rather than starting a run that would do nothing.

## What is deliberately unfinished

- The effect list is one row per label with a dropdown. Whether that is the
  right shape is **undecided** — changing one effect across many labels is N
  edits today. Opinions welcome.
- **"Process dataset…"** still exists and still writes a _copy_ of the dataset.
  It is superseded by step 19 and will go.
- A label can be asked for by only one prompt. Several prompts feeding one
  label is designed but not built.

## Reporting

Say which numbered step, which **Pass if** clause failed, and what you saw
instead. If it involves the timeline, the frame range matters — the server logs
every staged edit with its label, action and span, so a range makes it findable.
