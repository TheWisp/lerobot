# Held-object attachment policy

The live trial reads all grasp-assumption and held-pose correction thresholds from one `attachment` object in its rig JSON. `AttachmentRuntimeLimits.from_config` validates that object once; the planner and pose updater receive the same resulting policy. These are trial parameters, not properties of the dowel or ring.

| Parameter                  | Meaning                                                                                                                                                                                                             |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `motor_history_capacity`   | Number of measured joint samples retained to align a camera observation with the gripper at image capture time.                                                                                                     |
| `max_motor_sample_gap_s`   | Largest gap between joint samples that may bracket a camera image.                                                                                                                                                  |
| `max_unverified_age_s`     | Optional maximum time since the grasp assumption or last independent held observation. `null` keeps a rigid grasp assumption active until release or contradictory evidence; the replay must label it as predicted. |
| `max_observation_shift_m`  | Translation change accepted directly, and consistency limit between successive image-supported candidates for a larger correction.                                                                                  |
| `max_observation_turn_deg` | Matching rotation limits for those two decisions.                                                                                                                                                                   |
| `max_pregrasp_pose_age_s`  | Maximum age of the object pose used to seed the grasp assumption.                                                                                                                                                   |

The current SO-107 trial sets `max_unverified_age_s` to `null`. The old 20 s setting stopped the 2026-10-20 19:12:46 local trial during its ring approach, before the insertion contact interval. Elapsed time alone supplied no evidence that the object had slipped. The 15 mm and 15° limits no longer categorically reject a larger correction: a later independent image can confirm a visual proposal that explains more of the aligned mask and depth than the gripper prediction. If both poses remain plausible and the gripper prediction itself fits aligned depth within the configured fit tolerance, that prediction stays available and the replay marks the visual ambiguity. A contradicted or unsupported gripper prediction still withdraws the attachment for control. These limits remain provisional trial parameters, not calibrated confidence or object properties. See [pose flow](pose_flow.md).

The [example trial JSON](trial_config.example.json) also exposes the planner's IK sample and retiming budgets, evidence wait, and every causal group-tracking limit. The live launcher requires these values in its rig JSON so a trial cannot silently inherit a different internal default.

In Run → FLASH, **Inspect trial parameters** reads the selected rig JSON without moving the robot. The panel highlights the held-pose correction gate, held-prediction expiry, first-pose wait, and direct/group disagreement limits, then shows the full configuration. Each live attempt saves the effective values in its regular dataset at `flash/v1/trial_config.json`. The highlighted 20 s `first_pose_timeout_s` is only a startup wait; it is unrelated to the disabled `max_unverified_age_s` held-prediction expiry.

`causal_tracking.max_pose_disagreement_translation_m` and `max_pose_disagreement_rotation_rad` gate whether two tracker poses disagree at the modeled object center. They are independent of the RGB-D fit tolerance. Their current 10 mm and 0.15 rad values preserve the previous behavior, but are provisional and should be calibrated against recorded discrepancies rather than treated as object properties.

The GUI recording stores `held_prediction` separately from the independent tracker `accepted` pose. It also stores `held_prediction_at_camera` when measured motor samples bracket the displayed image time. The latter is used for the camera overlay; it is computed retrospectively for inspection and is not substituted for the planner's latest motor-time prediction. If no bracket is available, the UI labels the latest prediction as such. Older recordings lack these fields; their stationary tray outline is an old tracker state, not the pose the held-to-target planner used.

For a still-unverified scene-group hypothesis, `causal_tracking.static_prediction_max_s` permits a bounded stationary prediction when its tracked support points disappear. The prediction retains its last direct-observation time and `stationary_prior` provenance in the replay; it is not a new RGB-D measurement. A formerly verified moving group cannot silently become a stationary prior when its support points expire. The local insertion trial currently uses 4.5 s to cover the measured blind approach from the last direct dowel view to the grasp event. This is a trial assumption about an undisturbed object on its support, and it expires if no direct or group evidence returns. The generic example config leaves the prior disabled (`null`).

The fixed-rate controller now suspends a generated connection if its reference becomes stale, cancels unissued commands, and resumes that same endpoint from measured joints when fresh evidence returns. It records `interval_suspended` and a new `interval_start` in the replay. Contact samples cannot be restarted this way: a stale reference during demonstrated motion still interrupts the attempt. The top-level `max_wait_for_evidence_s` trial parameter bounds the pause, while `max_pose_age_s` remains the immediate freshness gate. This prevents variable perception latency from causing an immediate free-space abort without stretching the evidence-age limit indefinitely.

The same evidence-wait parameter bounds an unmet entry or completion milestone. Test records `milestone_wait` with the interval and milestone name, then reports failure with the latest verdict and reason if no fresh confirming evidence arrives before the limit. A true verdict received before the limit advances normally. This is a bounded failure path, not an automatic retry policy.

A demonstrated interval can begin only when its first sample is continuous with the issued joint boundary. If a moved reference makes that first sample exceed a joint-speed limit, the runtime inserts a generated entry connection to that sample, using the nearest preceding or following connection's annotated free-space speed. The demonstrated local clock starts after the connection completes; gripper events remain in the demonstrated interval. This is attempted once per interval entry, so a still-discontinuous entry reports failure instead of looping. Mid-interval speed violations remain failures because their contact samples cannot be silently retimed.
