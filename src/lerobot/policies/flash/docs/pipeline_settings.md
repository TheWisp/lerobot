# FLASH experiment pipeline settings

Live camera setup also has RealSense depth filters (spatial, temporal, hole filling), all off by default for FLASH. They can be switched while the camera runs. Depth is first aligned to the color image; the camera then retains both that aligned map **before** software filters and the aligned map **after** filters. The tracker uses the latter. The Depth and 3D views have a **Highlight filled holes** toggle: pink means a pixel had zero depth before filters and a positive depth afterward. It includes values created by the temporal filter as well as explicit hole filling; it does not mark measured values merely adjusted by smoothing. Remaining zero depth stays absent in 3D. Recent history and saved LeRobot episodes keep both aligned maps for the same frame, along with the applied filter state and revision. Neither map is the untouched native depth-sensor grid. Decimation is fixed off to keep depth pixels aligned with the color image and mask. A saved episode stores both maps rounded to whole millimetres, so changing camera filters requires a new capture. Camera-filter comparisons are not interchangeable with rerunning a saved clip using different observation thresholds.

Live camera setup offers **RealSense depth (default)**, **LingBot-Depth-v0.5**, **Fast-FoundationStereo**, and **Lite Any Stereo V2-S/M/L/H** as mutually exclusive depth inputs to the tracker. LingBot-Depth-v0.5 takes aligned RGB and sensor depth. Fast-FoundationStereo and all four Lite Any Stereo V2 sizes take synchronized RealSense left/right infrared images. Their disparity outputs are converted to metric depth and projected into the color camera. The projection fills only single-pixel sampling gaps where neighboring depths agree; depth steps and larger holes remain unknown. Models load before camera capture starts and cannot be switched without starting a new session. The whole model depth map is experimental and may disagree with valid sensor measurements; choosing it changes the geometry used by the tracker, so it is not a certified correction. In recent history and saved episodes, sensor depth remains the camera record. Processed frames retain model depth separately; in replay, **Show tracked model depth** selects it for the Depth and 3D views. **Highlight filled holes** marks only model/filtered depth in pixels where the preceding sensor map was empty; it does not identify model changes to nonempty sensor pixels. Stereo sessions also record the synchronized infrared pair and calibration. Older recordings without infrared cannot be rerun with a stereo model. LingBot-Depth-v0.5 can be tried on existing aligned RGB-D after the offline rerun path is connected to this selector.

The optional worker environment needs the upstream `mdm` package and its v0.5 weights for LingBot-Depth-v0.5. Lite Any Stereo V2 needs `onnxruntime-gpu` and a matching S/M/L/H ONNX checkpoint; set `LEROBOT_LAS2_ONNX` (H) or `LEROBOT_LAS2_S_ONNX` / `_M_ONNX` / `_L_ONNX` if they are not in their default cache locations. Each LAS2 checkpoint must be exported for **480×864** input (the 848-pixel infrared image is padded eight pixels on each side). Fast-FoundationStereo defaults to a local **480×864 TensorRT engine** at `~/.cache/flash-foundationstereo/fixed-480x864-d192-i8/fast_foundationstereo.engine`. Set `LEROBOT_FOUNDATION_STEREO_MODEL` to a different `.engine` or an explicit `.onnx` trial. An engine must be rebuilt for the installed GPU and TensorRT version; a missing/incompatible engine produces a start error rather than silently using the slower dynamic ONNX export. The live status shows depth-model time separately from mask and tracking time; these timings do not measure depth accuracy. Missing dependencies produce an explicit start error; no model loads with RealSense depth. The [LingBot pilot](../../../../../docs/proofs/flash-contact-observation/temporal-depth-pilot/README.md) includes held-out sensor-pixel checks: it improved the dish but did worse than simple interpolation on other objects. No model has passed a tracking-quality benchmark here, so all remain opt-in.

The Fast-FoundationStereo engine here comes from NVIDIA's [C-Fast-FoundationStereo checkpoint](https://huggingface.co/nvidia/c-fast-foundationstereo), using the authors' [single-ONNX exporter](https://github.com/NVlabs/Fast-FoundationStereo/blob/master/scripts/make_single_onnx.py) at 480×864, 8 refinement iterations, and maximum disparity 192. The published dynamic-size ONNX uses maximum disparity 416; the [authors recommend 192](https://github.com/NVlabs/Fast-FoundationStereo/blob/master/readme.md) for ordinary ranges. The runner repeats grayscale rectified IR into three channels, pads 848 to 864 pixels on the right, applies ImageNet normalization externally, and converts disparity to metric depth using the measured IR focal length and baseline. The C checkpoint omits the legacy `normalize` argument required by the exporter; set `model.args.normalize = True` after loading it, as in NVIDIA's published ONNX graph. With this host's PyTorch 2.11, the exporter also needs `dynamo=False` in `torch.onnx.export` to use its intended tracing path. Build the engine from that fixed ONNX with TensorRT 11, then set `LEROBOT_FOUNDATION_STEREO_MODEL` to its path if different from the default. This host has a validated **FP32** engine; an FP16 engine has not been validated. On five recorded tray IR pairs, warm engine inference took about 30 ms and the complete depth path about 63 ms on an RTX 5090, versus about 93 ms and 127 ms for the published dynamic ONNX through CUDA ONNX Runtime. Those frames establish deployment speed and near-equivalent output on this tray, not tracking quality across scenes.

Open **Run → FLASH → Pipeline settings** beside the selected video. Fresh live sessions use **LK + surface fit + groups + growing surface + Kalman**. Recorded experiments retain their saved settings; use the same complete configuration for a fair live/replay comparison. The JSON contains settings for the next rerun. Retired SciPy settings migrate to the new surface fitter; saved playback keeps its original matcher label. **Rerun this scene with these settings** validates and runs it. Playback itself never recomputes poses.

This is the restart experiment pipeline. It does not configure robot control. Saved-mask benchmarks reuse segmentation, so SAM/detection options are listed but not executed. Shared matching replaces the legacy object-crop matcher. Live-only scheduling options have no effect in the sequential benchmark.

Each optional section may be `null`. Groups require the surface experiment. Fixed/growing and group/non-group comparison methods select `grow` and `retain_unobserved_pose` themselves. Every effective setting is saved with results and included in cache identity. A changed configuration reruns the scene; it does not reinterpret an old result.

Tracking and growth have separate acceptance thresholds. Tracking defaults to 25% overlap within 5 mm; growth requires 75% within 3 mm before adding or confirming patches. An addition also needs 95% consistency with earlier retained depth/masks and 80% of its points measured again within 3 mm. These are experimental settings, not calibrated confidence: a geometrically ambiguous fit can still pass. Rejecting growth leaves pose tracking active. Initializing the first partial surface has no previous surface to compare against.

New surface experiments default to **Kalman filtering with a 25% geometry rejection allowance**. This is an empirical research default, not calibrated confidence. The allowance applies to aggregate point disagreement; it never permits a connected surface patch in measured empty space. It is separate from the stricter growth thresholds above. Candidate selection and filter-off remain available. Noise values are assumptions, not measured confidence. `depth_tolerance_m` and `max_visible_outlier_fraction` test direct contradictions in every mode, including with uncertainty disabled. The field remains in the uncertainty section for saved-configuration compatibility. Missing observations still allow group prediction. The mode does not estimate the probability that an object remains attached to its group.
Kalman mode propagates a 6D covariance with camera changes, consecutive measured group motion and time-scaled process noise. Current visible-surface information corrects the prediction in constrained directions. Innovation checks use both prediction and observation uncertainty. The legacy `reset_on_geometry_conflict=true` policy can restart the filter at a geometry-compatible proposal; setting it to `false` keeps the innovation check even when the previous prediction conflicts with depth/mask. A later geometry rejection restores the filter state. Rejected updates never grow the surface. Depth-normal constraints currently determine observation uncertainty; outline and image constraints used by fitting are omitted, so sideways motion on a flat patch can lag. Shared sensor biases and mistaken group membership remain limitations.

The shared fresh-session recipe uses one bounded surface fit from the current motion estimate, with measured depth and mask checking its output. It enables depth-range cleanup and one retained fit view. Kalman reset on geometry conflict is disabled. Outline coverage is a soft preference with weight 0.5, not a rejection threshold. Older saved playback keeps its original results; rerunning uses the current single-fit pipeline. Newly exposed sides may be absent from the stored surface, so a strong coverage preference can bias a fit. Dated comparisons and their limitations are in the [research log](../../../../../docs/proofs/flash-tracker-restart/RESEARCH.md).

For CLI use, `flash_tracker_experiment` accepts `--config` (a JSON object containing `vision_pipeline`), `--surface-experiment-config`, `--group-experiment-config`, and `--shared-matching-config`. The GUI uses the complete sectioned JSON below. `retain_motion_reference` corresponds to `--retain-motion-reference`.

Regenerate this reference with `python -m benchmarks.flash_pipeline_settings --write-reference <path>`. Defaults come from `surface_session_config.defaults()`, shared with the live debugger; they include the current research recipe over the compatibility dataclass defaults. Units appear in names: `_m` metres, `_px` pixels, `_s` seconds.
