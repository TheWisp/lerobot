# Tracking evidence used by FLASH

The runnable FLASH path and the research adapters have different contracts.
[`sealed_demo_import.py`](../sealed_demo_import.py) prepares the existing SO-107
insertion recording. [`live_trial.py`](../live_trial.py) uses a SAM3/DINO/RGB-D
direct pose backend; [`causal_service.py`](../causal_service.py) adds point and
verified environment-group predictions when configured. The same causal
service can now process recorded frames during demo extraction when its
annotation supplies `causal_tracking`. Previously prepared bundles have not
been regenerated by this code change, and the demo path still uses the
recorded gripper prediction for held motion. The offline tracker
review in [`demo_tracker_candidates.py`](../demo_tracker_candidates.py) creates
versioned pose candidates for a demo. Applying one changes selected demo pose
samples, not the live backend or its appearance reference bank.

| Evidence                                                                                                                                                                           | What it establishes                                                                                                                                                                                                                                                                                    | What it does not establish                                                                                                                                                            |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Full-pose benchmark](../../../../../docs/proofs/flash-full-pose-benchmark/README.md)                                                                                              | Complete Point2Pose is a strong causal candidate, but no method won across nine 31-frame annotated RGB-D clips. On moving bleach its median point-transport error was 18.2 mm versus 7.4 mm for LiteTracker plus a common fit. On the hard cracker clip it produced a pose on only 5/30 scored frames. | A globally best tracker, true contact-point accuracy, or live end-to-end rate. The other point methods were compared through a shared fitter, not their native complete pose systems. |
| [Dowel rotation](../../../../../docs/proofs/flash-visible-surface-benchmark/DOWEL_ROTATION.md)                                                                                     | Point2Pose followed the visible shaft through 118/121 frames; fixed first-view point fits often lost it. TrackEverything's native 3D point output was more useful than lifting its predicted pixels with measured depth in this clip.                                                                  | The position of the hidden inserted end or complete symmetry-resolved orientation.                                                                                                    |
| [Visible-surface benchmark](../../../../../docs/proofs/flash-visible-surface-benchmark/README.md)                                                                                  | Point identity, query growth, mask/depth support and integrated publication age can be measured separately. A live SAM3 step raised p90 estimate age in a paced probe to about 99 ms while the 30 Hz consumer kept ticking.                                                                            | That a dot inside the mask is the same material point, or that isolated tracker FPS is the rate of fresh FLASH poses.                                                                 |
| [Recorded tracker disagreement](../../../../../docs/proofs/flash-tracker-comparison/EVIDENCE.md) and [moving pose audit](../../../../../docs/proofs/flash-moving-pose/EVIDENCE.md) | Mask choice, correspondence and pose fitting can disagree even on the same aligned RGB-D image; a low surface residual alone can coexist with a wrong object-frame branch.                                                                                                                             | That any one of SAM, depth, Point2Pose or a group prediction is an unconditional authority.                                                                                           |
| [Cross-episode experiments](../../../../../docs/proofs/flash-cross-episode/README.md) and [drift audit](../../../../../docs/proofs/flash-drift-features/EVIDENCE.md)               | Partial view-to-view matches and temporally tracked point cohorts can transfer some geometry, but smooth surfaces and occlusion create identity and rigid-fit drift.                                                                                                                                   | Reliable transfer of an arbitrary invisible landmark across a demo and a live rollout.                                                                                                |
| [Local preparation and trials](evidence_status.md)                                                                                                                                 | The demo's held pose during insertion is predicted from a pregrasp estimate and recorded gripper motion; the recent redesign has a visually upright placement and a separate completed command sequence that fell after release.                                                                       | An independently verified hidden-tip pose or task-success signal.                                                                                                                     |

The common boundary is a timestamped pose proposal with source, reference-frame
version and observability. The scene estimator can carry a prediction through
occlusion, compare competing proposals with measured RGB-D and reject a
contradiction. The planner must not read a predicted pose as an independently
observed contact point. Changing the default tracker requires a causal,
end-to-end comparison on the same objects and a contact-point reference; the
benchmarks above do not justify changing that default by model name alone.
